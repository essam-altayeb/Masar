# مسار — الشركات والعقارات
### مكتب الطيب للمحاماة والاستشارات القانونية · الوساطة العقارية

نظام خفيف ببوابتين:
- **الشركات (مكتب المحاماة):** متابعة الشركات التي تزورونها، من الزيارة وبطاقة العمل، إلى إرسال الخطاب عبر واتساب أو البريد، ومعرفة متى فتحت الشركة الملف التعريفي، حتى التوكيل وحساب عمولة نور (30%).
- **العقارات (الوساطة العقارية):** العقارات وملاكها، والعملاء وطلباتهم، والمطابقة بينهم بالنسبة المئوية، وإرسال العقارات للعميل عبر واتساب مع صفحة صور خاصة به، والمعاينات والصفقات والعمولات.

| الحساب | البوابات |
|---|---|
| عصام (المدير) | الشركات + العقارات |
| نور عيسى (الشريكة) | الشركات + العقارات |
| محمد علي (وسيط عقاري) | **العقارات فقط** — لا يرى أي شيء من الشركات |

كل شخص يدخل ببريده و**رقمه السري الخاص**. والفصل بين البوابتين مطبّق في قاعدة البيانات نفسها (RLS)، وليس في الواجهة فقط.

## ما الذي يقدمه النظام

| | |
|---|---|
| **الحسابات** | كل شخص بحسابه ورقمه السري، ومن يملك البوابتين ينتقل بينهما بزر «الشركات / العقارات» أعلى الشاشة. |
| **الزيارات الميدانية** | سجّل الجولة (التاريخ والمنطقة)، وأضف كل شركة بسرعة مع صورة بطاقة العمل من كاميرا الجوال. |
| **المسار** | كل شركة تمر بمراحل: مستهدفة ← زيارة ← تواصل ← اهتمام ← اجتماع ← عرض ← **توكيل** (أو مؤجلة / غير مهتمة). |
| **الخطابات** | قوالب جاهزة (منها خطابكم التعريفي بالعربي والإنجليزي) تتعبأ تلقائياً باسم الشركة والشخص، ويعدّلها عصام أو نور في أي وقت، ويمكن تعديل النص قبل كل إرسال. |
| **واتساب والبريد** | زر واحد يفتح محادثة واتساب بالخطاب جاهزاً، أو البريد. وعلى الجوال يمكن مشاركة ملف البروفايل PDF نفسه داخل واتساب. |
| **الرابط الخاص لكل شركة** | داخل كل خطاب رابط صفحة خاصة باسم الشركة: الملف التعريفي، الفريق، الخدمات، انستغرام، وأزرار التواصل وطلب موعد. **ويظهر لكم متى فتحوها** وماذا ضغطوا. |
| **المتابعات** | بعد كل إرسال يُحدَّد موعد متابعة تلقائياً (3 أيام افتراضياً)، وتظهر المتابعات المستحقة في الرئيسية مع «إرسال متتابع» لإنهائها بسرعة. |
| **العمولات** | عند التوكيل تُسجَّل الأتعاب المحصّلة، ويُحسب نصيب نور (30%) تلقائياً مع متابعة ما صُرف وما تبقى. |
| **ملف Excel** | الشركات الـ12 من ملف المتابعة الحالي تُستورد تلقائياً عند أول تشغيل، ويمكن تصدير كل الشركات إلى Excel في أي وقت. |
| **على الجوال** | يعمل كتطبيق: من المتصفح اختر «إضافة إلى الشاشة الرئيسية». |

### بوابة العقارات
| | |
|---|---|
| **العقارات** | أراضٍ (سكنية/تجارية/صناعية/استثمارية)، شقق، فلل، بيوت، عمارات، محلات ومكاتب، مخازن، مزارع واستراحات، قيد الإنشاء، مشاريع جديدة، أو «نوع آخر». لكل عقار ملف كامل: رقم العقار، الغرض والحالة (متاح / محجوز / مباع / مؤجر)، السعر وسعر المالك، الموقع (المحافظة، المنطقة، المجمع، الطريق، المبنى، الخريطة 📍)، المواصفات والمميزات، الصور والفيديو، والمستندات (وثيقة الملكية، المخطط...). |
| **العملاء** | بيانات العميل ونوعه (مشتري / مستأجر / مستثمر / مالك) ومصدره والموظف المسؤول، و**طلبه** بخيارات قابلة للفلترة: الأنواع، الغرض، الميزانية من–إلى، المناطق، الغرف والحمامات والمواقف والمساحة، الفرش. |
| **المطابقة ⭐** | في صفحة كل عميل تظهر العقارات المتاحة المطابقة لطلبه **بنسبة مئوية** مع السبب (ضمن الميزانية، المنطقة، الغرف...). وفي صفحة كل عقار تظهر العملاء الذين يناسبهم. وصفحة «ابحث عن عقار لعميل» للبحث السريع. |
| **الإرسال للعميل** | اختر العقارات ← رسالة واتساب جاهزة باسم العميل وتفاصيل العقارات + **رابط صفحة خاصة به** فيها الصور والتفاصيل. يضغط العميل «يعجبني» أو «لا يناسبني» أو «أريد معاينة» فيظهر ردّه مباشرة في سجله، ويظهر لكم متى فتح الصفحة. |
| **المتابعة (Timeline)** | سجل كامل لكل عميل: أول تواصل، ماذا طلب، ما أُرسل له، ما أعجبه وما رفضه وسبب الرفض، المعاينات، الملاحظات، وموعد المتابعة القادم مع تذكير. |
| **تقييم العميل** | Cold 🟢 ← Warm 🟡 ← Hot 🟠 ← Very Hot 🔴 — يرتفع تلقائياً عندما يحدد العميل ميزانيته ومنطقته، ويطلب أكثر من عقار، ويحجز معاينة (ويمكن تعديله يدوياً). |
| **الملاك** | ملف لكل مالك: هاتفه وواتساب، نوع الاتفاق، نسبة العمولة، تاريخ الاتفاق وانتهائه (تنبيه قبل الانتهاء)، وكل عقاراته في مكان واحد. |
| **الصفقات والعمولات** | لكل صفقة: العقار، العميل، المالك، الموظف، السعر، طريقة الدفع والحالة. ويحسب النظام: سعر الصفقة ← العمولة ← نصيب الموظف ← ربح المكتب. الصفقة المكتملة تجعل العقار «مباع/مؤجر» والعميل «تمت الصفقة». نسبة الموظف وصرف عمولته يحددها المدير فقط. |
| **لوحة الأرقام** | عقارات متاحة/محجوزة/مباعة/مؤجرة، العملاء والنشطون والـHot، متابعات اليوم، المعاينات القادمة، مبيعات الشهر والعمولات وأفضل موظف. |

## تجربة النظام قبل الرفع
افتح الملف `public/index.html` من جهازك مباشرة (نقرتين). يفتح **نسخة تجريبية** فيها الشركات الـ12 وبيانات عقارات افتراضية للتجربة. اختر الحساب وأدخل رقمه السري التجريبي: عصام `1111`، نور `2222`، محمد علي `3333` (في النظام الحقيقي يختار كل شخص رقمه بنفسه). ما تضيفه في التجربة يبقى في متصفحك فقط ولا يصل لقاعدة البيانات، والروابط الخاصة والبريد المباشر يعملان بعد النشر فقط.

## النشر (مرة واحدة — حوالي 15 دقيقة، بدون أي تعديل في الكود)

### 1) رفع الملفات إلى GitHub
1. فك ضغط `masar-altayeb.zip` على الكمبيوتر، وادخل مجلد `masar`.
2. افتح [github.com/new](https://github.com/new)، واكتب اسم المستودع `masar`، واختر **Private**، ثم اضغط **Create repository**.
3. في صفحة المستودع اضغط الرابط **uploading an existing file**.
4. حدّد **كل ما بداخل** مجلد `masar` واسحبه إلى الصفحة دفعة واحدة — وليس المجلد نفسه، وليس ملف الـ zip، وليس `index.html` وحده.
5. اضغط **Commit changes**.

> للتأكد: يظهر `package.json` و `vercel.json` في الصفحة الرئيسية للمستودع مباشرة.

### 2) قاعدة البيانات في Supabase (من حسابك)
1. ادخل حسابك في [supabase.com](https://supabase.com/dashboard)، ثم اضغط **New project**.
2. اختر مؤسستك، واكتب الاسم `masar`، واضغط **Generate a password** واحفظ كلمة المرور.
3. المنطقة: **South Asia (Mumbai)** — الأقرب للبحرين. اترك باقي الخيارات كما هي، ثم اضغط **Create new project** وانتظر دقيقتين.
4. من القائمة الجانبية افتح **SQL Editor**، ثم اضغط **New query**.
5. افتح ملف `supabase/schema.sql` وانسخ كل محتواه والصقه، ثم اضغط **Run** (وإن ظهر تنبيه اضغط **Run this query**). يجب أن تظهر كلمة Success.
6. افتح **Project Settings** ثم **Data API**، وانسخ رابط المشروع (Project URL).
7. افتح **Project Settings** ثم **API Keys**، وانسخ المفتاح العام (يبدأ بـ `sb_publishable`) والمفتاح السري (يبدأ بـ `sb_secret` — لا تشاركه مع أحد).
8. مستحسن: افتح **Authentication** وأطفئ خيار **Allow new users to sign up** — حسابات مسار تُنشأ من داخل النظام فقط.

> اجعل مسار في مشروع مستقل، وليس داخل مشروع ميزان: حسابات مسار (ومنها حساب محمد) ستكون مستخدمين في نفس المشروع، وأي جدول في ميزان مسموح لكل مستخدم مسجّل سيصبح مكشوفاً لهم.

### 3) النشر على Vercel
1. افتح [vercel.com/new](https://vercel.com/new)، واختر مستودع `masar`، ثم اضغط **Import**.
2. قبل النشر افتح قسم **Environment Variables**، وأضف المتغيرات الثلاثة بالأسماء التالية بالضبط:

| المتغير | قيمته |
|---|---|
| `SUPABASE_URL` | رابط المشروع |
| `SUPABASE_PUBLISHABLE_KEY` | المفتاح العام |
| `SUPABASE_SECRET_KEY` | المفتاح السري |

3. اضغط **Deploy** وانتظر حتى يظهر رابط الموقع.

> المشاريع القديمة في Supabase قد تعرض مفتاحي anon و service_role بدلاً من المفاتيح الجديدة: ضعهما في `SUPABASE_ANON_KEY` و `SUPABASE_SERVICE_ROLE_KEY` — النظام يقبل الاسمين.

### 4) أول دخول
1. افتح رابط الموقع (مثل `https://masar-xxxx.vercel.app`).
2. أنشئ حسابك (البيانات مكتوبة مسبقاً — اختر رقمك السري فقط، 8 خانات أو أكثر). لأمان النظام، أول حساب مدير يُنشأ فقط ببريد المكتب `lawyer.essamaltayeb@gmail.com` (لاستخدام بريد آخر أضف في Vercel المتغير `ADMIN_EMAIL`).
3. بعدها مباشرة تظهر نافذة **بوابة نور عيسى**: اكتب بريدها ورقماً سرياً لها (البوابتان مختارتان)، ثم اضغط **إنشاء الحساب**.
4. أرسل لنور رابط الموقع وبريدها ورقمها السري، ويمكنها تغييره من الإعدادات.
5. **بوابة محمد علي (العقارات فقط):** من الإعدادات افتح **الفريق والبوابات** ثم **+ عضو**. اكتب الاسم «محمد علي»، والصفة «وسيط عقاري»، وبريده، ورقماً سرياً له، والصلاحية «عضو / موظف». اترك **العقارات** فقط مختارة (بدون الشركات)، واكتب نسبته من عمولة الصفقات إن أردت، ثم اضغط **إنشاء الحساب**. وأرسل له الرابط وبريده ورقمه السري.

## تحديث قاعدة البيانات لاحقاً
- عند أي تحديث جديد للنظام: ارفع الملفات الجديدة إلى GitHub فوق القديمة، ثم شغّل ملف `supabase/schema.sql` الجديد مرة أخرى في **SQL Editor** بنفس الطريقة. الملف آمن للتشغيل أكثر من مرة ولا يمسح البيانات.
- أو اجعلها تلقائية: أضف في Vercel متغيراً رابعاً باسم `POSTGRES_URL`. قيمته من Supabase: اضغط **Connect**، واختر **Session pooler**، وانسخ الرابط، وضع كلمة مرور قاعدة البيانات مكان `[YOUR-PASSWORD]`. بعدها تُحدَّث الجداول وحدها مع كل نشر.
- لو فتحت الموقع وظهرت شاشة «تهيئة قاعدة البيانات»: شغّل ملف `schema.sql` في **SQL Editor** كما في الخطوة 2.

### بديل: بدون حساب Supabase
يمكن إنشاء قاعدة البيانات من داخل Vercel نفسه: في مشروعك على Vercel افتح **Storage**، ثم **Create Database**، واختر **Supabase**، واربطه بمشروع `masar` لكل البيئات، ثم أعد النشر (**Redeploy**). بهذه الطريقة تُضاف المفاتيح وتُنشأ الجداول تلقائياً، لكن قاعدة البيانات تكون باشتراك منفصل عبر Vercel.

> جداول النظام كلها تبدأ بـ `crm_` (الشركات) أو `re_` (العقارات).

## (اختياري) إرسال البريد من النظام مع إرفاق البروفايل PDF
بدون هذه الخطوة يعمل زر البريد عبر تطبيق البريد في جهازك مع رابط الملف. لإرساله مباشرة مع **إرفاق ملف البروفايل**:

1. افتح [myaccount.google.com/apppasswords](https://myaccount.google.com/apppasswords) من حساب بريد المكتب (يتطلب تفعيل التحقق بخطوتين)، وأنشئ كلمة مرور تطبيق باسم `Masar`.
2. في Vercel افتح **Settings** ثم **Environment Variables**، وأضف:
   - `GMAIL_USER` وقيمته `lawyer.essamaltayeb@gmail.com`
   - `GMAIL_APP_PASSWORD` وقيمته الرمز المكوّن من 16 حرفاً
3. أعد النشر من **Deployments** بزر **Redeploy**. سيظهر في نافذة الإرسال خيار «أرسل البريد مباشرة من النظام مع إرفاق البروفايل PDF».

الردود تصل إلى بريد من أرسل الخطاب (عصام أو نور)، ونسخة الرسالة تبقى في «المرسل» في Gmail.

## كيف يعمل الرابط الخاص
- كل شركة لها رابط مثل `https://موقعكم/p/3f9a1c2b7d4e` يوضع تلقائياً داخل الخطاب.
- عند فتحه تظهر صفحة باسم الشركة: الشعار، الترحيب، فريق التواصل (عصام ونور)، من نحن، مجالات الممارسة، صفحات البروفايل كاملة، تحميل PDF، الخدمات، انستغرام، وأزرار واتساب / طلب موعد — بالعربية أو الإنجليزية.
- يظهر لكم في الرئيسية وفي صفحة الشركة: **«فتحوا الرابط — قبل ساعتين»**، و**«طلبوا موعداً 🔥»** إن ضغطوا الزر.
- عندما تفتحون الرابط بأنفسكم وأنتم مسجّلو الدخول لا تُحتسب الزيارة (يظهر شريط «معاينة»).
- صفحة المكتب العامة بدون اسم شركة: `https://موقعكم/p` (مناسبة لبايو انستغرام).

### صفحة العقارات للعميل (بوابة العقارات)
- عند إرسال عقار أو أكثر لعميل يُنشأ له رابط مثل `https://موقعكم/r/k3m9x2p7qa4rtz` داخل رسالة الواتساب.
- الصفحة باسم العميل: صور العقارات (تمرير بالإصبع)، السعر، المواصفات، المميزات، الوصف، وبيانات الوسيط للتواصل — بالعربية أو الإنجليزية.
- لا تظهر فيها بيانات المالك ولا سعره ولا العنوان الدقيق ولا الملاحظات الداخلية ولا وثيقة الملكية.
- أزرار «👍 يعجبني» و«👎 لا يناسبني» (مع السبب) و«📅 أريد معاينة» تُسجَّل فوراً في سجل العميل، وطلب المعاينة يفتح واتساب الوسيط ويضع العميل في متابعات اليوم.
- «معاينة صفحة العميل» من نافذة الإرسال تفتحها لكم دون أن تُحتسب.

## الأمان والصلاحيات
- لكل شخص رقمه السري الخاص، ولا يرى البيانات إلا أعضاء الفريق المسجّلون (حماية على مستوى قاعدة البيانات RLS)؛ أي حساب آخر لا يرى شيئاً.
- **البوابات:** من لا يملك بوابة «الشركات» (مثل محمد علي) لا تعيد له قاعدة البيانات أي شركة أو زيارة أو خطاب أو دفعة — حتى لو حاول الوصول من خارج التطبيق. ولا يستطيع أي عضو تغيير بواباته أو صلاحيته بنفسه.
- **المدير (عصام):** كل شيء في البوابتين، بما فيه الفريق والإعدادات وتسجيل الأتعاب، ونسبة الموظف في صفقات العقارات وصرف عمولته، والحذف النهائي.
- **الشريكة (نور):** الشركات والعقارات، وترى عمولتها ودفعاتها دون تعديلها.
- **محمد علي:** العقارات فقط — يضيف ويعدّل العقارات والعملاء والملاك والمعاينات والصفقات، ويحذف الصور والفيديو فقط. لا يغيّر نسبته أو صرف عمولته، ولا يعدّل صفقة مكتملة، ولا يحذف عقاراً أو عميلاً أو مالكاً أو صفقة أو مستنداً أو سجل المتابعة (هذا للمدير).
- **ملفات العقارات** في Supabase Storage (تُنشأ تلقائياً عند أول رفع): الصور والفيديو بروابط طويلة غير قابلة للتخمين لتظهر في صفحة العميل، والمستندات (وثيقة الملكية، المخطط...) خاصة تُفتح بروابط مؤقتة (15 دقيقة) لأعضاء العقارات فقط.
- صفحة الشركات العامة لا تكشف إلا اسم الشركة واسم الشخص وبيانات تواصل المكتب، وصفحة العقارات للعميل لا تكشف بيانات المالك أو العنوان الدقيق (المجمع والطريق والمبنى والخريطة). الصور تُضغط قبل الرفع فتُزال منها بيانات الموقع (GPS)، أما الفيديو فيُرفع كما هو — إن كان الهاتف يسجّل الموقع في الفيديو فقد يبقى فيه.
- أبقوا مستودع GitHub **خاصاً (Private)** لأن ملف قاعدة البيانات يحتوي بيانات الشركات المستوردة.

- خطة Vercel المجانية (Hobby) مخصّصة للاستخدام الشخصي غير التجاري؛ للاستخدام التجاري الرسمي تُنصح خطة Pro.
